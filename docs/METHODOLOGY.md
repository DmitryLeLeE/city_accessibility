# Методика и обоснование

[English version](METHODOLOGY.en.md)

Документ описывает математическую модель приложения, допущения и то, чем они обоснованы. Все числовые параметры собраны в `WALK` и `CONFIG` (`js/config.js`); числа в таблицах ниже получены из формул кодом, а не подобраны вручную. Формулы, которые проверяются в `tests/run.mjs` независимо (численным интегрированием и моделированием), отмечены знаком ✔.

## 1. Что измеряется

Пешая доступность — это **время** от точки *x* до ближайшего объекта категории *c* вдоль реальной сети путей:

```
t_c(x) = min over объектов j категории c  T(x → j)
```

где `T` — минимальное ожидаемое время пешего пути. Изохрона уровня τ — множество, достижимое за время не более τ:

```
Iso(τ, x₀) = { x : T(x₀ → x) ≤ τ }
```

Это *кумулятивная* мера доступности (число возможностей в пределах порога времени) и, в сочетании с функцией затухания (раздел 8), *гравитационная* мера в классификации Geurs & van Wee (2004), восходящей к Hansen (1959). Пороги 5/10/15 мин отвечают концепции «15-минутного города» (Moreno et al., 2021).

## 2. Сеть

Пути OSM образуют граф *G = (V, E)*, вложенный в плоскость. Рёбра длиннее 40 м делятся на равные части: это даёт точную привязку точек к сети и гладкие контуры изохрон. Исключены `motorway`, `construction`, пути с `foot=no`/`access=private|no`, площадные объекты (`area=yes`). Мелкие изолированные компоненты (меньше 25 узлов) отбрасываются, чтобы привязка не попадала на «острова».

Расстояния — геодезические (haversine, R = 6 371 008,8 м). Для растеризации используется локальная равнопромежуточная проекция вокруг центра области; на масштабе города (десятки км) искажение длины пренебрежимо мало (порядка 10⁻⁴).

## 3. Время ребра

```
t_e = ℓ_e · φ_e / v₀
```

`ℓ_e` — длина, `v₀` — свободная скорость пешехода (по умолчанию 4,8 км/ч = 1,33 м/с; регулируется). Это типичное значение: Тоблер (1993) даёт 5,04 км/ч на ровной местности; полевые измерения на тротуарах — 1,2–1,5 м/с, 1,2 м/с принято в HCM как расчётное значение для смешанной популяции (Knoblauch et al., 1996; Highway Capacity Manual, 6th ed.).

Множитель `φ_e ≥ 1` собирается из тегов OSM:

| Фактор | Множитель | Обоснование |
|---|---|---|
| Лестница | 1,8 | подъём/спуск по ступеням существенно медленнее ходьбы по ровной поверхности |
| Покрытие (`surface`) | 1,0 (асфальт, бетон) … 1,4 (грунт, трава) … 1,8 (снег, лёд) | снижение скорости на мягких и скользких покрытиях |
| Качество (`smoothness`) | 1,0 … 2,0 | то же |
| Уклон (`incline`) | см. ниже | функция Тоблера |
| Проезжая часть без тротуара | 1,2–1,4 (по классу) | вынужденная ходьба по обочине, снижение скорости и комфорта |
| `sidewalk=separate` | 1,1 | у дороги предпочитаем отдельно нарисованный тротуар |

**Уклон.** Скорость по Тоблеру: `v(s) = 6·exp(−3,5·|s + 0,05|)` км/ч, *s* — доля уклона. Направление пути по ребру в OSM неизвестно, поэтому берётся среднее время подъёма и спуска относительно ровной местности:

```
φ(s) = ½ · ( v(0)/v(s) + v(0)/v(−s) ),   φ(0) = 1,  φ(10 %) ≈ 1,2
```

Рельеф по цифровой модели высот **не используется**: уклон учитывается только там, где он размечен в OSM.

## 4. Ожидание на переходах

Дорога в графе — осевая линия, а пешеход идёт по тротуару и обязан пересекать проезжую часть. Время ожидания — случайная величина; в маршрутизации используется её **математическое ожидание**.

### 4.1. Светофор (Вебстер, HCM) ✔

Пешеход приходит в момент, равномерно распределённый на цикле длиной *C*; если приходит в пешеходную зелёную фазу *g* — не ждёт, иначе ждёт до начала следующей зелёной:

```
E[W] = (1/C) ∫_g^C (C − t) dt = (C − g)² / (2C)
```

Параметры по классам дорог (цикл *C*, пешеходная зелёная *g*, с): service 40/12, residential 60/15, tertiary 75/15, secondary 90/15, primary 100/15, trunk 110/15. Формула проверена численным интегрированием в тестах.

### 4.2. Нерегулируемый переход (формула Адамса) ✔

Поток машин — пуассоновский с интенсивностью λ (авт/с); пешеход начинает переход, если следующая машина придёт не раньше чем через критический интервал *t_c*, иначе пропускает машину и оценивает интервал заново. Математическое ожидание задержки (Adams, 1936):

```
E[D] = ( e^{λ·t_c} − λ·t_c − 1 ) / λ
```

Пешеход пересекает направления по очереди, поэтому дорога делится пополам: поток направления *q/2*, критический интервал `t_c = (w/2)/v_c + t_s`, суммарная задержка `d = 2·E[D](q/2, t_c)`. Здесь *w* — ширина проезжей части (при наличии тега `lanes` — `lanes × 3,25 м`), *v_c* = 1,2 м/с, *t_s* = 3 с (потерянное время на старт, HCM). Формула проверена моделированием пуассоновского потока (отклонение < 3 %).

Размеченный нерегулируемый переход — ×0,7; «зебра» — ×(1 − η), η = 0,6 — доля уступающих водителей, не менее 1 с. В России водители обязаны уступать на нерегулируемом переходе, поэтому такая оценка консервативна.

## 5. Перекрёстки как кольцо концов тротуаров

Если считать, что на перекрёстке пешеход просто «пересекает боковую улицу», теряются типичные эффекты: на Т-образном перекрёстке с противоположной от примыкания стороны переходить не нужно; поворот «налево» требует перехода, а «направо» — нет; крупная дорога без переходов — барьер. Чтобы получать их без специальных правил, состояние пешехода — пара *(дуга, сторона дороги σ ∈ {справа, слева})*.

Узел *v* с *k* ветками моделируется кольцом из 2*k* вершин. Ветки упорядочены по азимуту по часовой стрелке; у ветки *i* есть левый `L_i` и правый `R_i` концы тротуара:

- **угол** — `R_i` соединён с `L_{i+1}` рёбрами нулевой стоимости (тротуар огибает угол между соседними ветками);
- **переход** — `L_i` соединён с `R_i` рёбрами стоимостью `w_i` — ожидание на переходе ветки *i* по формулам раздела 4 (для пешеходной ветки — 0, это один и тот же тротуар).

Стоимость транзита из состояния *(a, σ)* в *(b, σ′)* — длина кратчайшего пути между соответствующими концами в кольце (Флойд — Уоршелл, 2*k* ≤ 16 вершин). Пример: на Т-образном перекрёстке путь «прямо по стороне, противоположной примыканию» стоит 0; «прямо по стороне примыкания» — *w* боковой улицы; «налево» — *w* дороги, по которой пришли.

На небольших улицах (ранг ≤ 2) сторону можно сменить в любой точке за `w` (ожидание пересечения проезжей части без разметки); на остальных — только на перекрёстках и в узлах с размеченным переходом. Поэтому крупная дорога без переходов — барьер, а сеть тихих улиц проходима поперёк почти свободно, как в жизни.

**Корректность.** Все веса неотрицательны, не зависят от времени и зависят только от пары (вход, выход), поэтому на графе состояний работает обычный алгоритм Дейкстры (Dijkstra, 1959): он даёт минимум ожидаемого времени в рамках модели. Сложность `O(|S| log |S|)`, `|S| ≤ 2·|A|`, где *A* — множество дуг; на сетке 8 × 8 км (≈100 тыс. дуг) один пробег занимает десятки миллисекунд. Численно проверено на случайной сети с разными классами дорог, светофорами, зебрами и калитками: время `T(x→y)` совпадает с `T(y→x)` с точностью 10⁻¹² с (так и должно быть для ходьбы без одностороннего движения).

## 6. Привязка точек к сети

Точка привязывается к ближайшему узлу в радиусе: объекты 150 м, здания 200 м, старт 300 м. Участок от точки до сети идёт по дворам, поэтому его время умножается на 1,25. Если узел принадлежит крупной дороге (ранг ≥ 3), добавляется **¼ ожидания перехода**: узлы привязки не знают, на какой стороне дороги стоит объект; для двух независимых точек с вероятностью ½ нужен переход, и это ожидание делится поровну между концами.

Следствие: `T` определено на «свободных» концах, поэтому на тройках точек неравенство треугольника может нарушаться (проход через промежуточную точку позволяет бесплатно сменить сторону). На изохроны и индекс это не влияет — они считаются одним пробегом от одного источника.

## 7. Построение изохроны

`Iso(τ)` строится как «буфер» вокруг достижимых узлов, а не выпуклая или альфа-оболочка (она ошибочно накрывает кварталы без проходов):

1. узлы с `T ≤ τ` — на растр с шагом *h* = 40 м;
2. расширение на одну клетку (Чебышёв): зона охватывает точки в 40–80 м от достижимой сети — учёт расстояния от дорожки до входа;
3. трассировка границ заполненных клеток (внешние контуры — против часовой стрелки, отверстия — по часовой; при касании по диагонали контуры не склеиваются);
4. сглаживание Чайкина (две итерации срезания углов, Chaikin, 1974);
5. отверстия площадью меньше 4 га заливаются, крупные (реки, железные дороги, парки без проходов) сохраняются.

Погрешность положения границы порядка 1,5*h* ≈ 60 м, то есть ≈ 45 с ходьбы. Площадь завышена за счёт расширения: на открытой манхэттенской сетке изохрона 5 мин даёт ≈ 0,41 км² при теоретическом ромбе радиуса *v·τ* = 400 м площадью 2*r*² = 0,32 км² (+28 %); тест требует, чтобы отношение лежало в пределах 0,9–1,45. Для сравнения районов и проблемных зон это не важно (смещение системное), для абсолютных площадей — учитывайте. Это стандартный компромисс сервисных зон по сети (см. O'Sullivan et al., 2000); при необходимости *h* и расширение меняются в `isochroneGeometry`.

## 8. Индекс доступности

Время до ближайшего объекта категории считается одним пробегом Дейкстры из всех объектов сразу (мультиисточник, эквивалент виртуального источника, связанного с объектами рёбрами нулевой стоимости). Для точки *i* и категории *c* — время `t_c(i)` в минутах, балл — кусочно-линейная функция затухания с усечением:

```
s(t) = 100                                   при t ≤ 5
s(t) = 100 · (20 − t) / 15                    при 5 < t < 20
s(t) = 0                                     при t ≥ 20
```

Индекс точки — среднее баллов выбранных категорий; индекс района *D* — взвешенное среднее по точкам спроса:

```
I_D = Σ_{i∈D} w_i · s̄(i) / Σ_{i∈D} w_i
```

Усечённое линейное затухание — простейшая «ядерная» функция расстояния в гравитационных мерах доступности (Hansen, 1959): убывает монотонно и обращается в ноль за пределами разумной пешей досягаемости. Пороги 5 и 20 мин — параметры (`CONFIG.index`): ≤ 5 мин (≈ 400 м) считается «рядом», ≥ 20 мин — «вне пешей доступности». Дополнительно для каждой категории считаются доли спроса в пределах заданных порогов (по умолчанию 5/10/15 мин) и взвешенная медиана времени.

**Спрос.** Численность жителей в OSM отсутствует, поэтому применяется дазиметрический принцип (Mennis, 2003): жилым зданиям приписывается вес, пропорциональный этажности (`building:levels`; квартирные дома без тега — 5, остальные — 1; нежилые типы исключены фильтром). Это прокси, а не перепись: этажность не равна числу жителей, часть зданий не размечена. Режим «По улицам» заменяет здания узлами сети с весом, равным длине улиц. Режим «Свои данные о населении» берёт точки (или центры полигонов) из загруженного GeoJSON с весом из свойства `pop` / `population` / `people` / `weight` (иначе 1); точка привязывается к ближайшему узлу сети в радиусе привязки зданий, непривязанные пропускаются. Полигоны сводятся к центру масс внешнего кольца, весь вес — в эту точку; для крупных полигонов (районов) лучше подавать точки.

**Сценарии «что если».** Гипотетический объект добавляется к источникам Дейкстры своей категории (привязка как у обычных объектов), расчёт повторяется, а показатели сравниваются с базовым расчётом без добавленных объектов (индекс, число проблемных зон, доли жителей в пределах порога). Объект — точечный, вход один; парк как площадной объект не моделируется.

## 9. Проблемные зоны

Область разбивается на ячейки 150 м со взвешенным средним индексом. Ячейка «проблемная», если индекс < 35 (для равных весов это в среднем ≈ 14,8 мин до объектов) и её спрос не ниже половины медианного (отсекает единичные здания на окраинах). Связные группы (8-соседство) образуют зоны; для каждой указываются доля общего спроса, площадь и категория с наименьшим баллом.

Результаты зависят от нарезки районов (проблема изменяемой площадной единицы, Openshaw, 1984), поэтому доступны и административные границы, и квадратные сетки разного размера, а проблемные зоны не привязаны к границам районов.

## 10. Проверка

`npm test` (54 теста, без сети и браузера) проверяет:

- **задержки на перекрёстках:** прямо, Т-образный, поворот, «лесенка» по диагонали, светофор/«зебра»/без разметки, явный переход `footway=crossing`, калитки, тупики;
- **формулы** Вебстера и Адамса — численным интегрированием и моделированием Монте-Карло;
- **множители пути:** лестницы, покрытия, уклон, тротуары;
- **геометрию изохрон:** площадь относительно эталонного ромба на манхэттенской сетке, вложенность, замкнутость и ориентацию контуров, сохранение отверстий;
- **сверку на случайных сетях** (случайные классы дорог, светофоры, «зебры»): время не меньше, чем по прямой при максимальной скорости (с допуском 0,1 % на float32); при большей скорости время не растёт; разбор маршрута согласован (старт + ходьба + ожидание = итог); при нулевых параметрах ожиданий время равно `длина × φ / v₀`;
- **разбор маршрута:** `track` не меняет результат Дейкстры, число событий «светофор» на тестовом пути равно числу пересечений;
- **параметры модели:** пересчёт таблиц ожиданий, игнорирование некорректных значений, сброс;
- **отказоустойчивость:** падение зеркала, обход всех зеркал, некорректные ответы (HTML, `remark` о таймауте, нет `elements`), таймаут, повторные раунды, отмена, истечение карантина, переход геокодера на Photon;
- **локализацию:** у каждой строки интерфейса есть перевод, плейсхолдеры совпадают;
- привязку, индекс, проблемные зоны и разбор данных OSM.

## 11. Разбор маршрута и прозрачность

Дейкстра в режиме `track` запоминает для каждого состояния (дуга, сторона) предшественника, величину ожидания и тип перехода. По ним `tracePath` восстанавливает путь и раскладывает время: `T = T_подход + T_ходьба + T_ожидания + T_выход`. События ожидания (светофор, «зебра», размеченный, нерегулируемый переход, калитка, переход посреди квартала) выводятся с координатами.

Параметры модели (циклы, зелёные фазы, ширины, потоки, скорость перехода, множители) можно менять в интерфейсе (окно «Как считается»); таблицы ожиданий пересчитываются по тем же формулам (разделы 4–5), а граф перестраивается, так как задержки на перекрёстках «запечены» в матрицах колец. «Журнал расчёта» фиксирует, что именно загружено (числа путей, светофоров, объектов, зданий), размер графа и время этапов.

## 12. Источники данных и отказоустойчивость

Данные берутся из публичных сервисов, которые бывают недоступны, поэтому запросы выполняются с перебором зеркал (`js/failover.js`):

- 5 зеркал Overpass; сбоем считаются HTTP-ошибки, таймаут попытки (70 с), обрыв сети, ответ не в JSON, отсутствие `elements`, `remark` о нехватке времени/памяти;
- упавшее зеркало получает «карантин» `15 с · 2^(k−1)` (до 5 мин), порядок обхода — сначала здоровые, чаще отвечавшие раньше; если упали все — до 3 кругов с паузой 1,2 с, 2,4 с;
- ответ 429/503 с `Retry-After` учитывается (до 8 с);
- геокодер: Nominatim → Photon;
- загруженные тайлы данных (0,03° × 0,045°) кэшируются в памяти и в IndexedDB на 7 дней, поэтому после сбоя повторяются только недостающие;
- результат не зависит от того, какое зеркало ответило: данные — одна и та же OSM (с точностью до задержки репликации между зеркалами, обычно минуты).

## 13. Ограничения и как их снимать

- **Средние вместо распределений.** В маршрутизации используются ожидания; оптимальный маршрут по ожиданиям может отличаться от оптимального при учёте разброса (неравенство Йенсена). Для оценки ширины неопределённости — менять параметры (окно «Как считается») и скорость.
- **Параметры не калиброваны под конкретный город.** Потоки, ширины, циклы светофоров заданы по классам дорог. Для точных оценок их следует заменить замерами; архитектура это допускает: `roadFlow`, `roadWidth`, `signalCycle`, `signalGreen` — один объект.
- **Рельеф**, интенсивность и фазы реальных светофоров, погода, время суток, возраст и мобильность пешеходов не учитываются.
- **Полнота OSM.** Если тротуары и переходы не размечены, модель опирается на классы дорог. Качество результата в городе ограничено качеством карты в нём.
- **Прокси населения.** См. раздел 8; свои данные о населении заменяют прокси, но их качество и дата — на вашей стороне.
- **Сценарии** показывают изменение доступности по модели, а не прогноз использования объекта: вместимость, график работы и очереди не учитываются.
- **Завышение площади изохроны** на ≈ 20–30 % из-за буфера растра (раздел 7).
- **Кэш и актуальность:** данные в локальном кэше до 7 дней старше OSM; кнопка «Очистить кэш» снимает это.

# City Accessibility

Веб-приложение для анализа **пешей доступности городской инфраструктуры** в любом городе мира. Всё работает в браузере на открытых данных [OpenStreetMap](https://www.openstreetmap.org): без сервера, ключей API и регистрации.

**Демо:** https://dmitrylelee.github.io/city_accessibility/

## Возможности

| Возможность | Как работает |
|---|---|
| **Изохроны 5 / 10 / 15 минут** | Клик по карте → кратчайшие пешие пути по сети → контуры зон. Минуты (до 4 значений, 1–30) и скорость пешехода настраиваются, маркер можно перетаскивать. |
| **Доступность больниц, школ, парков** | Для каждой зоны — число объектов и время до ближайшего. Дополнительно: аптеки, детские сады, продуктовые магазины, остановки транспорта (список — в `js/config.js`). |
| **Анализ пешеходной сети** | Граф из путей OSM. Время учитывает перекрёстки и переходы (светофоры, «зебры», ожидание по классу дороги, сторона дороги), покрытие, лестницы, уклон, калитки, отсутствие тротуаров. |
| **Поиск проблемных районов** | Ячейки 150 м с низким индексом объединяются в нумерованные проблемные зоны с долей спроса, площадью и категорией, которой не хватает больше всего. |
| **Сравнение районов** | Административные границы OSM (`admin_level`, автоопределение) или квадраты 500 м – 2 км. Таблица с сортировкой: индекс, доля жителей в зоне ≤ 15 мин, медиана времени. Экспорт CSV и GeoJSON. |

## Быстрый старт

```bash
git clone https://github.com/DmitryLeLeE/city_accessibility
cd city_accessibility
npm start        # python3 -m http.server 8080 → http://localhost:8080
```

Сборка не нужна: статические файлы и ES-модули. Открывать `index.html` через `file://` нельзя — модули требуют HTTP.

**GitHub Pages:** Settings → Pages → Source: *GitHub Actions*. Workflow `.github/workflows/pages.yml` на каждый push в `main` запускает тесты и публикует сайт.

## Как пользоваться

1. Найдите город в поиске или сместите карту. Слой карты переключается значком в левом верхнем углу.
2. **Изохроны из точки:** кликните по карте. Скорость, минуты и категории пересчитывают результат сразу.
3. **Анализ города:** наведите карту на нужный участок → «Рассчитать для видимой области». Область — видимая часть карты, не больше 8 × 8 км (`maxAnalysisSpanKm`); большой город анализируйте по частям. Загруженные фрагменты данных кэшируются на время сессии.

## Как считается время

Данных о реальной скорости нет, поэтому время собирается из модели пешехода по тегам OSM:

```
время = длина × множитель пути (покрытие, лестницы, уклон, тротуар) / скорость
      + ожидание на переходах (светофор, «зебра», нерегулируемый переход)
```

- **Перекрёстки.** Пешеход идёт по тротуару, поэтому состояние — (дуга, сторона дороги). Каждый перекрёсток — кольцо концов тротуаров, где перейти ветку стоит ожидание перехода. Отсюда получаются: «прямо» = перейти боковую улицу; на Т-образном перекрёстке с «глухой» стороны переходить не нужно; поворот «на свою сторону» бесплатен; крупная дорога без переходов — барьер.
- **Ожидание** считается по формулам теории транспортных потоков из параметров дорог, а не подобрано: у светофора по Вебстеру `(C − g)² / (2C)`, на нерегулируемом переходе по формуле Адамса `(e^{λt} − λt − 1) / λ`. Обе проверены в тестах независимо (численным интегрированием и моделированием Монте-Карло).
- **Индекс доступности** по категории: 100 баллов при ≤ 5 мин, 0 при ≥ 20 мин, между ними линейно; итог — среднее по выбранным категориям, взвешенное по «жителям» (прокси: этажность жилых зданий).

| Ранг дороги | Светофор, с | «Зебра», с | Без разметки, с |
|---|---|---|---|
| service | 9,8 | 1,0 | 0,1 |
| residential | 16,9 | 1,0 | 0,7 |
| tertiary | 24,0 | 1,0 | 2,2 |
| secondary | 31,3 | 2,2 | 5,6 |

**Полное обоснование** — вывод формул, допущения, оценка погрешностей, ограничения и литература — в [docs/METHODOLOGY.md](docs/METHODOLOGY.md).

## Настройка

Всё в `js/config.js`:

| Параметр | Что меняет |
|---|---|
| `CONFIG.defaultCenter`, `defaultZoom` | стартовый вид карты |
| `CONFIG.speedKmh`, `bands` | скорость и изохроны по умолчанию |
| `CONFIG.maxAnalysisSpanKm` | максимальная сторона области анализа |
| `CONFIG.index` | пороги индекса (`bestMin`, `worstMin`, `problemBelow`) |
| `CONFIG.overpass` | зеркала Overpass API |
| `CATEGORIES` | категории объектов (Overpass-фильтры + `match`) |
| `WALK` | параметры модели пешехода: циклы светофоров, потоки и ширины дорог, множители покрытия |

Чтобы откалибровать модель под свой город, замените в `WALK` значения `roadFlow`, `roadWidth`, `signalCycle`, `signalGreen` замеренными: таблицы ожиданий пересчитаются автоматически.

## Подложка карты

Ключи не нужны. По умолчанию используются тайлы [OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/) (требуется атрибуция, нагрузка должна быть умеренной) и светлая подложка Esri (удобна для наложений, масштаб до 16). Подложки CARTO с 2024 года требуют ключа или лицензии, поэтому не используются. Для сайта с большим трафиком подставьте своего провайдера тайлов в `baseMaps` (`js/app.js`).

## Тесты

```bash
npm install
npm test         # 34 теста, без сети и браузера
```

Проверяются: задержки на перекрёстках (прямо, Т-образный, поворот, светофор/«зебра»/без разметки, переход `footway=crossing`, калитки, тупики), формулы Вебстера и Адамса, множители пути, геометрия изохрон (площадь на эталонной сетке, вложенность, отверстия), привязка, индекс, проблемные зоны, разбор данных OSM.

## Ограничения

- Overpass API — общий бесплатный ресурс. Приложение грузит данные небольшими фрагментами (сеть, светофоры и переходы, объекты), ограничивает параллелизм и переключает зеркала, но при частых запросах сервер может ответить ошибкой — подождите и повторите.
- Качество результата ограничено полнотой OSM: не нанесённые проходы, переходы и тротуары модель не видит; площадные пешеходные зоны (`highway=pedestrian` + `area=yes`) в сеть не попадают.
- Только пешеходное передвижение. Рельеф берётся из тега `incline`, если он есть; реальные циклы светофоров, интенсивность движения, погода и время суток не учитываются.
- Параметры модели — значения по умолчанию по классам дорог, а не замеры конкретного города (подробнее в разделе 11 методики).
- Численности населения в OSM нет: вес по этажности зданий — прокси.
- Административные границы районов нарезаны по-разному; если нужного уровня нет, выберите `admin_level` вручную или режим «Квадраты».

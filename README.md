# City Accessibility

Веб-приложение для анализа **пешей доступности городской инфраструктуры** в любом городе мира. Работает целиком в браузере на открытых данных [OpenStreetMap](https://www.openstreetmap.org): ни сервера, ни ключей API, ни регистрации.

## Что умеет

| Возможность | Как это работает |
|---|---|
| **Изохроны 5 / 10 / 15 минут** | Клик по карте → кратчайшие пешие пути по сети улиц и троп (алгоритм Дейкстры) → контуры зон. Значения минут и скорость пешехода настраиваются. |
| **Доступность больниц, школ, парков** | Для каждой зоны считается число объектов и время до ближайшего. Дополнительно: аптеки, детские сады, продуктовые магазины, остановки транспорта (список категорий — в `js/config.js`). |
| **Анализ пешеходной сети** | Граф строится из путей OSM (`highway=*`, без автомагистралей и закрытых проходов). Время пути учитывает **перекрёстки и переходы** (светофоры, «зебры», ожидание по классу дороги), покрытие, лестницы, уклон, калитки и отсутствие тротуаров — подробности в разделе «Методика». |
| **Поиск проблемных районов** | Видимая область разбивается на ячейки 150 м; связные группы ячеек с индексом доступности ниже 35 объединяются в нумерованные **проблемные зоны** с указанием, чего им не хватает больше всего. |
| **Сравнение районов** | Административные границы из OSM (`admin_level`, определяется автоматически) или квадратная сетка 500 м – 2 км. Таблица с сортировкой: индекс, доля жителей в зоне ≤ 15 мин и медиана времени по каждой категории. Экспорт в CSV и GeoJSON. |

## Быстрый старт

```bash
git clone https://github.com/DmitryLeLeE/city_accessibility
cd city_accessibility
npm start            # python3 -m http.server 8080 → http://localhost:8080
```

Сборка не нужна: это статические файлы и ES-модули. Открывать `index.html` напрямую (`file://`) нельзя — модули требуют HTTP.

**Публикация на GitHub Pages:** Settings → Pages → Source: *GitHub Actions*. Workflow `.github/workflows/pages.yml` сначала запускает тесты, затем выкладывает сайт.

## Как пользоваться

1. Найдите город в поиске слева или просто сместите карту.
2. **Изохроны из точки:** кликните по карте. Маркер можно перетаскивать, зоны пересчитываются.
3. **Анализ города:** наведите карту на нужный участок и нажмите «Рассчитать для видимой области». Область анализа — видимая часть карты, но не больше 8 × 8 км (`maxAnalysisSpanKm`); для большого города анализируйте его по частям. Загруженные фрагменты данных кэшируются на время сессии.

## Методика

Данных о фактической скорости нет, поэтому время считается из модели пешехода, которая собирается из тегов OSM. Все числа лежат в `WALK` (`js/config.js`) и легко правятся.

**Время = длина × множитель пути / скорость + ожидание на переходах.** Скорость по умолчанию 4,8 км/ч (слайдер).

### Множители пути

| Что | Множитель |
|---|---|
| Лестница (`highway=steps`) | ×1,8 |
| Покрытие (`surface`): асфальт, бетон — ×1; плитка, брусчатка, щебень — ×1,05–1,3; грунт, трава — ×1,35–1,4; грязь, песок, снег — ×1,7–1,8 | |
| Качество (`smoothness`): `bad` ×1,3 … `horrible` ×1,7 | |
| Уклон (`incline`) | по формуле Тоблера, усреднено по подъёму и спуску: 10 % ≈ ×1,2 |
| Дорога без тротуара (`sidewalk=no`) | tertiary ×1,2, secondary ×1,3, primary/trunk ×1,4 |
| Крупная дорога без информации о тротуарах | primary/trunk ×1,15 |
| Тротуар нарисован отдельно (`sidewalk=separate`) | ×1,1 у дороги — предпочитаем нарисованный тротуар |

### Перекрёстки и переходы

Пешеход идёт по тротуару, а в графе дорога — осевая линия. Поэтому у пешехода есть **сторона дороги** (справа/слева по ходу), а каждый перекрёсток разбирается как кольцо концов тротуаров: у каждой ветки есть левый и правый конец, соседние ветки соединены углом (бесплатно), а чтобы попасть с одного конца ветки на другой, нужно **перейти эту ветку**. Из этого без особых правил получается:

- идя прямо, пересекаем боковую улицу на своей стороне; на Т-образном перекрёстке с «глухой» стороны переходить не нужно;
- поворот на «свою» сторону бесплатен, поворот на противоположную требует перехода;
- «лесенка» по диагонали в сетке кварталов дешевле Г-образного пути — меньше переходов, как и в жизни;
- крупная дорога без переходов — барьер: перейти её можно только на перекрёстке или в узле с отмеченным переходом; на небольших улицах (service, residential) переходят где угодно.

Ожидание при переходе дороги, секунды (среднее; `WALK`):

| Класс дороги | светофор | «зебра» | без разметки |
|---|---|---|---|
| service, living_street | 10 | 1 | 1 |
| residential, unclassified | 20 | 2 | 2 |
| tertiary | 22 | 3 | 5 |
| secondary | 28 | 5 | 10 |
| primary | 32 | 7 | 16 |
| trunk | 38 | 10 | 24 |

Размеченный переход без светофора — 70 % от «без разметки»; на дорогах от 4 полос без светофора ожидание ×1,3. Светофор определяется по `highway=traffic_signals`, `crossing=traffic_signals`, `crossing:signals=yes` в узле; «зебра» — по `crossing=zebra|marked`. Калитка, шлагбаум, турникет — +4 с, закрытые (`access=no|private`, `foot=no`) блокируют проход. Если пешеход идёт вдоль дороги мимо явного перехода (отдельный путь `footway=crossing`), задержки нет.

### Остальное

- **Привязка к сети.** Объекты привязываются к ближайшему узлу не дальше 150 м (здания 200 м, стартовая точка 300 м); путь от точки до сети идёт по дворам, поэтому ×1,25. Если точка привязана к крупной дороге, добавляется четверть ожидания перехода — объект может быть на другой стороне. Парки доступны с любой точки границы (вход каждые ~60 м по контуру).
- **Жители.** Реальной численности в OSM нет, поэтому используется прокси: каждое жилое здание весит столько, сколько у него этажей (`building:levels`; квартирные дома без тега — 5, остальные — 1). Режим «По улицам» берёт узлы сети с весом по длине улиц и считается быстрее.
- **Индекс доступности** по категории: 100 баллов при ≤ 5 мин, 0 при ≥ 20 мин, между ними линейно. Итоговый индекс — среднее по выбранным категориям, взвешенное по «жителям». Пороги — в `CONFIG.index`.
- **Проблемные зоны:** ячейки 150 м с индексом < 35 и спросом не ниже половины медианного, 8-связные группы.
- **Контур изохроны:** достижимые узлы → растр 40 м → расширение на 1 клетку → трассировка границ → сглаживание Чайкина; отверстия меньше 4 га заливаются.

### Чего модель не знает

Рельефа (только тег `incline`, если он есть), реальных циклов светофоров, интенсивности движения, погоды и времени суток. Ожидания — средние по классу дороги: их стоит откалибровать по замерам для вашего города, если нужна точность выше «правдоподобной».

## Структура

```
index.html          разметка
css/style.css       оформление
js/config.js        параметры, категории объектов, палитры
js/geo.js           геометрия (haversine, проекция, point-in-polygon, площади)
js/walkmodel.js     модель пешехода: множители пути, флаги узлов, ожидание на переходах
js/graph.js         граф, кольца перекрёстков, привязка точек, Дейкстра по (дуга, сторона)
js/isochrone.js     построение контуров
js/overpass.js      Overpass/Nominatim: тайлы, кэш, повторы, зеркала
js/analysis.js      индекс, районы, проблемные зоны, экспорт
js/app.js           интерфейс на Leaflet
tests/run.mjs       тесты ядра на синтетической сетке улиц
```

Тесты (`npm install && npm test`) проверяют ядро без сети: задержки на перекрёстках (прямо, Т-образный, светофор/зебра/без разметки, переход `footway=crossing`, калитки), множители пути, площадь и вложенность изохрон, «дырки» в контурах, привязку, индекс, разбор данных OSM.

## Ограничения

- Overpass API — общий бесплатный ресурс. Приложение грузит данные небольшими фрагментами (сеть, теги светофоров и переходов, объекты), ограничивает параллелизм и переключается между зеркалами, но при очень частых запросах сервер может ответить ошибкой; подождите и повторите.
- Площадные пешеходные зоны (`highway=pedestrian` + `area=yes`) и проходы через дворы, не нанесённые на карту, в сеть не попадают: качество результата зависит от полноты OSM в конкретном городе.
- Учитывается только пешеходное передвижение. Рельеф берётся лишь из тега `incline`; барьеры (заборы, железные дороги без переходов) — настолько, насколько они отражены в OSM.
- Административные границы районов бывают нарезаны по-разному; если нужного уровня нет, выберите `admin_level` вручную или режим «Квадраты».
